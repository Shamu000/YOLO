### batch size
```
推荐始终使用 batch=-1，交给 AutoBatch 自动选择，配合 nbs 来自动在不同设备之间调整学习率，保证学习平稳。
```
### lr0
```
使用 batch=-1（AutoBatch）并且保持 nbs=64，那么 lr0=0.01 是一个合理的默认值，适用于大多数情况.
```

### lrf
```yaml
lrf 决定了：从 lr0 开始，经过若干个 epoch 后，衰减到的最终学习率（final_lr = lr0 * lrf）。
通常 lrf = 0.01（默认值）已经适用于大多数情况，但在一些情况可以适当调节来提升训练表现。
```

| lrf 取值             | 后期学习率变化   | 适合场景             | 风险                            |
| -------------------- | ---------------- | -------------------- | ------------------------------- |
| **小 (如 0.01)**     | 学习率降得很低   | 精细收敛、非常稳定   | 可能太早陷入平稳，**loss 停滞** |
| **中 (如 0.05~0.1)** | 学习率适中降低   | 推荐常规训练使用     | 通常比较平衡                    |
| **大 (如 0.2~0.5)**  | 学习率后期仍较高 | 训练时间短、快速收敛 | 可能不够精细、波动大            |
| **极大 (如 1.0)**    | 学习率不下降     | 等价于常量学习率     | **易不收敛或振荡**              |

### optimizer

```
建议选择auto或者SGD
```

| Optimizer | 收敛速度 | 最终效果   | 是否适合你当前任务（关键点识别） | 特点说明                                    |
| --------- | -------- | ---------- | -------------------------------- | ------------------------------------------- |
| **SGD**   | 中       | 稳定       | ✅适合                            | 保守但稳，适合你现在模型结构和 batch 比较小 |
| **Adam**  | 快       | 容易过拟合 | ⚠️可能不太适合                    | 初期收敛快，后期不稳定                      |
| **AdamW** | 快       | 稳定       | ✅适合中大型模型                  | Transformer等常用，自带权重衰减             |
| **auto**  | 平衡     | 看模型     | ✅当前也可以用                    | 建议前期测试用 auto，后期锁定好选项         |

| 目标                       | 设置                                       |
| -------------------------- | ------------------------------------------ |
| 训练稳定、可控、适合长训练 | `optimizer='SGD'`                          |
| 快速试验、调参阶段         | `optimizer='AdamW'`, 搭配 warmup 充分      |
| 完全不懂怎么选             | `optimizer='auto'`（Ultralytics 会自动挑） |

### cos_lr

```
「200轮后 loss 停滞甚至变差」的场景下，使用余弦退火可以延缓后期学习率的下降幅度，保持模型“继续学习”的能力。开启 cos_lr=True 是提升你训练后期表现的一个很好的选择，尤其是当 loss 过早稳定或震荡时，可以显著改善训练效果。
```

| 方式         | 图示                 | 描述                                                 |
| ------------ | -------------------- | ---------------------------------------------------- |
| **线性衰减** | 📉 直线下降           | 学习率从 `lr0` 均匀下降到 `lr0 * lrf`                |
| **余弦退火** | 🔁 类似正弦波下半部分 | 初期下降快，中期平稳，后期接近 0，训练后期有“微调感” |

| 模式                     | 优点                   | 缺点                           | 适合情况                     |
| ------------------------ | ---------------------- | ------------------------------ | ---------------------------- |
| **cos_lr=False（线性）** | 简单直接，收敛稳定     | 后期学习率下降太快可能停止优化 | 数据多、任务复杂（你的情况） |
| **cos_lr=True（余弦）**  | 后期训练平稳，细致优化 | 初期下降太快可能欠拟合         | 微调、fine-tune、小模型      |

### close_mosaic

```html
close_mosaic 是用来“收尾”的，把模型从广义泛化调整为具体拟合。建议始终设定为一个合理的值，不要一直开着 mosaic 到最后
优点：
提高泛化能力
更适合训练初期阶段，模型快速收敛
缺点：
后期精度影响较大，因为拼图结构跟真实图像分布差别太大
```

| 你的情况                             | 建议设置                                    |
| ------------------------------------ | ------------------------------------------- |
| 模型小（如 yolo11n），训练 100~300轮 | `close_mosaic=10~15`（默认是 10，比较合理） |
| 数据很丰富，epoch 设置很多           | 可以设成 `20~30`，让后期更稳定              |

### hsv

```py
建议调参
hsv_h = 0.01   # 稍微提高一点色调变换
hsv_s = 0.3    # 降低饱和度变化，防止颜色偏离
hsv_v = 0.6    # 提高亮度增强幅度，更贴近亮暗多变的环境，或者调到更高比如0.8
```

| 参数    | 建议值            | 说明                                                 |
| ------- | ----------------- | ---------------------------------------------------- |
| `hsv_h` | **`0.01` 或更低** | 保持色调（Hue）稳定，否则红蓝容易被扰动，分类错误    |
| `hsv_s` | **`0.2 ~ 0.3`**   | 略微扰动饱和度，增强模型鲁棒性，但不过度改变颜色纯度 |
| `hsv_v` | **`0.5 ~ 0.8`**   | 提高亮度变化，模拟暗光下的亮暗分布差异，提升适应性   |

| 参数    | 作用内容       | 举例解释                                               | 建议设定                                |
| ------- | -------------- | ------------------------------------------------------ | --------------------------------------- |
| `hsv_h` | 色调扰动幅度   | 0.015 表示 ±0.015 的随机扰动（红可能变粉、蓝可能变青） | 小于等于 `0.01`，颜色敏感任务需控制得小 |
| `hsv_s` | 饱和度扰动幅度 | 0.7 表示 ±70% 的饱和度扰动（颜色从鲜艳变淡）           | 一般设 `0.2~0.4`，太高会让红蓝不清晰    |
| `hsv_v` | 亮度扰动幅度   | 0.4 表示 ±40% 的亮度变化（模拟光照强弱变化）           | 可设 `0.5~0.8`，适合光照不稳定环境      |

### translate

```py
推荐
translate = 0.05  ~ 0.1

太大的 translate 可能把装甲板“平移”到图像边缘甚至截掉，反而降低训练质量；
translate 和 mosaic 一起使用时，有时会产生部分目标被拼接得不完整的问题；
目标中如果有位置敏感内容（如数字），一定要小范围平移，否则位置混乱会影响训练
```

| 应用情况                             | 建议设置       | 原因                               |
| ------------------------------------ | -------------- | ---------------------------------- |
| 目标一般都比较靠近中心               | `0.05` ~ `0.1` | 适度增加模型对“边缘目标”的识别能力 |
| 目标在图像中经常出现不同位置         | `0.1` ~ `0.2`  | 增强模型泛化能力                   |
| 图像中有重要文字（数字等）容易被切掉 | `≤ 0.1`        | 避免平移后文字出界或被裁剪         |

### scale

```py
推荐
scale = 0.3 ~ 0.5   ✅

如果设置得太大，比如 scale=0.7~1.0，小目标会被缩得非常小，训练效果反而变差。
缩放后 YOLO 会自动处理 padding 和 anchor 匹配，但过小目标容易被判为背景。
不同于 imgsz=640 的输入 resize，scale 是用于增强阶段的图像变换
```

| 应用情景                          | 建议设置        | 说明                                     |
| --------------------------------- | --------------- | ---------------------------------------- |
| 目标大小变化不大（视角较固定）    | `scale=0.1~0.2` | 稳定模型训练，增强适度泛化               |
| 目标距离变化较多（远/近目标都有） | `scale=0.3~0.5` | 增强模型识别不同尺寸目标的能力           |
| 图像里有细节（如数字/图案）       | `scale≤0.5`     | 防止缩小时目标太小被“忽略”或锚点分配错误 |

### mosaic

```
作用：
将4张图片混合为1张；
原图会被缩放 → 平移 → 拼接；
广泛用于目标检测，提升小目标检测效果。
优点：
显著增强样本数量；
提高模型鲁棒性；
模拟目标在不同位置的出现。
缺点：
会改变目标几何结构，导致关键点与背景混杂；
对于“图案识别”、“灯条识别”这类视觉语义非常关键的任务可能会引入“异常图像结构”。
```

| 阶段         | 设置建议                                           |
| ------------ | -------------------------------------------------- |
| 前期训练     | ✅ 保持 `mosaic=1.0`（增强多样性）                  |
| 后期收敛     | 🔥 关闭 mosaic，比如 `close_mosaic=10`，10轮后关闭  |
| 图案识别优先 | ❗ 如果训练效果不好，可以试试 `mosaic=0.5` 降低扰动 |

### mixup

```py
作用：
将两张图按权重线性叠加；
标签也按比例合成；
常用于分类任务（如 ImageNet）。

```

### auto_augment & erasing

```py
auto_augment = None  # 禁用自动增强策略
erasing = 0.0        # 禁用随机擦除

🧽 erasing
✅ 功能：
随机擦除图像中的一块区域（通常用于分类任务）；
模拟遮挡、损坏；
在 ImageNet 等任务中可有效提升鲁棒性。
⚠️ 对任务的影响：
你需要检测的是灯条、文字、图案；
如果刚好擦除目标关键区域，会导致：
标签依然存在，但图像中“目标已不可见”；
错误地惩罚模型，训练信号变得不可靠；
尤其对关键点训练是灾难性的（遮住头却要你预测鼻子）；

auto_augment 是给图像分类任务设计的自动图像增强策略，如非特别测试和验证，不建议在关键点检测中使用，尤其是在需要识别图案、数字、颜色的任务中。
```

| 策略名称      | 简介                                                         | 特点                       |
| ------------- | ------------------------------------------------------------ | -------------------------- |
| `randaugment` | 从一堆图像增强操作中**随机选几种操作组合**使用（例如旋转、亮度、对比度、颜色调整等） | 高效、无需太多超参数       |
| `autoaugment` | 使用在 ImageNet、CIFAR 等上训练好的**增强策略表**，用于“系统性增强” | 更系统化但灵活性较低       |
| `augmix`      | 使用增强图像与原图**混合构建样本**，增强鲁棒性且保持语义一致性 | 泛化性强，适合鲁棒分类任务 |
