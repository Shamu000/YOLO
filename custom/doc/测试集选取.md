

**测试集 = “未来实战环境的缩影”**，它的唯一价值是 **验证泛化**，而不是再帮网络“学习”。





### Domin差异

```
机器人身上的装甲板通常有它自己独特的背景（机器人本体、运动中的抖动、视角、光照），而手持拍摄的装甲板背景相对干净、静止，光照也更可控。
⚠️ 这就造成了“训练/验证集 → 测试集”之间的 domain gap，如果 gap 太大，即使模型在手持图上表现很好，也不一定能迁移到实战场景。
```

在拍手持测试集的时候，尽量模拟实战环境：

- 摆放在机器人或类似金属结构前
- 加入运动模糊
- 不同光照（室内、室外、阴影）
- 不同视角（俯视、仰视、小角度倾斜）

### 缺少某些类别的数据

```
如果测试集中没有出现 5 号或“小装甲板”类别，那么你无法客观评估模型在这些类别上的性能——因为根本没有标签

但如果这两个类别在实际比赛中你不需要去识别，可以：

直接不在测试集里标注（也不拍摄）
或者即便拍了，也在评估时过滤掉这两个类别
```

- 在资源受限的情况下，用“手持装甲板”做测试集**可以暂时替代**，但要尽量缩小与实战场景的差距。
- 缺少的类别，如果比赛中**确实不需要**识别，就**不必**在测试集里添加；
- 通过 `classes=` 参数，或在 `datasets.yaml` 里只保留你要关心的那些 `names`，来让测试时只算那些类别的指标。

| 类别出现频次（测试集）          | 建议                                                         |
| ------------------------------- | ------------------------------------------------------------ |
| 常见类别（英雄、工程、前哨站…） | 50‑100 张/类（越多越好）。                                   |
| 罕见类别（基地装甲、小装甲）    | ≥ 30 张/类；如果拿不到，**15 张也行**，但务必多角度。        |
| 没法拍到的类别                  | 可以留 0 张，但在最终 mAP 里就会被计为缺测，可单独在实验报告里说明“不参与评估”。 |

### 比赛数据和模拟赛数据的选取

```

```

| 数据来源                                         | 作用                                                         | 理由                                                         |
| ------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **家里模拟赛拍的大量完整数据（Domain A）**       | **主力 训练集**                                              | 数量充足，用来学「共性」特征（网络收敛、对光照/角度的基础鲁棒性等）。 |
| **正式比赛现场少量未见过的真实数据（Domain B）** | **→ 先当 \*验证 / 测试集\*** （如果确实很少，建议再拆分 80 % fine‑tune + 20 % hold‑out） | 与最终部署环境同域，最能检验泛化；量小，直接塞进训练很容易被过拟合“淹没”。 |



#### 为什么不直接把比赛数据加入训练

**Domain Gap**

- 家里数据 ≈ 受控光照、背景干净；
- 比赛数据 ≈ 赛场灯光、对手反光、裁判服等；
   现场数据是真正的 **目标分布**，更应拿来检查模型是否仍然可靠，而不是再去「污染」它。

**数量少 → 易过拟合**

- 如果通通进 train，网络会很快记住这些稀有样本；
- 你就再也没有“未知”数据来评估了——调参时可能一直过拟合到这些小样本，却在下一场比赛翻车。



#### 流程总结

```
                ┌─────  Train Stage‑1 (大批量) ─────┐
                │                                    │
模拟赛大数据 --> │  Train 80%  (Domain A)            ↓
                │                                    │
                └─────  Val (Domain B 20%)  ─────────┘
                                    │
                                    ↓
           ┌───────────────  Train Stage‑2 (低 lr 微调) ────────────────┐
           │                                                          │
比赛现场数据 80% (已人工检查标签)  --> Fine‑tune / Re‑train few epochs   │
           │                                                          ↓
           └───────────────  ***最终测试***  (留出的 20% B) ──────────────┘

```

**Stage‑1**：只用家里大量数据 + 也可以随机掺一点比赛数据（但保留 20 % hold‑out）。

**Stage‑2**：把比赛数据里 80 % 作为 *few‑shot fine‑tune*，**学习 Domain‑B 特有的光照 / 反射**。

**最终评估**：永远用那 20 % *B‑hold‑out* 做最后一次 `val/test`，报告 mAP。

**以后再拿到新比赛图** → **只加进 Stage‑2 训练集**，但 `B‑hold‑out` 永远不动。

**数量非常少怎么办？**

- <50 张时干脆 **全部作为测试**；
- 训练时只靠家里数据 + 重度数据增强（调 HSV、噪声、亮暗、裁剪等）来逼近现场 Domain。

**batch & lr**

- Stage‑2 **lr 低 5 – 10×**，防止把已学到的“大特征”冲掉。
- `close_mosaic` 设得更小甚至关闭，让微调阶段别再做大拼图。

**数据增强**

- Stage‑1 保持你当前推荐的增强幅度；
- Stage‑2 适当减弱（如 `mosaic=0.2`、`hsv_*` 降 30 %），避免过强噪声干扰少量真实样本。
